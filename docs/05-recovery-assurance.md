# Recovery Assurance

## Принцип

Статус `Backup succeeded` означает только успешную запись. Fortiq отдельно измеряет,
можно ли обнаружить, разблокировать, прочитать и восстановить данные.

## Recovery Confidence

Показатель формируется из наблюдаемых сигналов, а не из ответа AI:

- свежесть последнего успешного snapshot относительно RPO;
- результат repository integrity check;
- успешность последнего test restore;
- наличие доступного независимого key path;
- наличие immutable/offline copy;
- возраст последней проверки recovery kit;
- наличие policy violations.

Формула и веса должны быть версионированы и объяснимы. Критический провал не может быть
скомпенсирован второстепенными положительными сигналами.

## Уровни проверки

1. **Metadata check:** snapshot и manifest доступны и проходят проверку целостности.
2. **Sample restore:** случайная стратифицированная выборка восстанавливается и сверяется.
3. **Application check:** восстановленные данные проходят профильную проверку формата.
4. **Full recovery drill:** периодическое восстановление заданного workload в изоляции.

## Отчёт

Каждый тест создаёт подписанную запись:

- repository и snapshot ID;
- использованный unlock path без секретов;
- объём и метод выборки;
- timestamps, duration и результат;
- версии engine и recovery tool;
- ошибки и remediation actions.

## Безопасность тестирования

Restore-test выполняется в изолированном каталоге или sandbox, не перезаписывает рабочие
данные и не запускает восстановленные исполняемые файлы. Содержимое удаляется согласно
политике после фиксации результата.
